Ordre de montage

  1. Vérifiez l'alimentation d'abord, à vide. Câblez piles, interrupteur, C4 et les découplages. Mesurez la tension avant d'insérer le moindre circuit intégré. Une inversion de polarité détruit tout en une seconde.
  2. Montez l'oscillateur seul, avec une résistance fixe de 150 kΩ à la place de la plante. C'est votre plante d'essai : elle ne sèche pas et ne change pas de valeur.
  3. Vérifiez l'oscillation sur la broche 3, à l'oscilloscope ou, à défaut, avec un petit haut-parleur en série avec un condensateur de 100 nF : vous devez entendre un sifflement grave. Avec 150 kΩ et 4,7 nF, la période théorique est de 1,14 ms, soit 878 Hz.
  4. Ajoutez le microcontrôleur et reliez la broche 3 du 555 à D2. Chargez un croquis minimal qui compte les interruptions et affiche la période sur le moniteur série. Ne passez pas à l'étape suivante avant que ce chiffre soit stable.
  5. Ajoutez le potentiomètre de seuil sur A0.
  6. Ajoutez la sortie MIDI et testez avec un moniteur MIDI logiciel avant de brancher un synthétiseur.
  7. Ajoutez les LED en dernier. Elles sont confortables mais consomment, et une LED mal câblée peut charger une broche.
  8. Remplacez la résistance fixe par les électrodes, via le câble blindé et l'embase J2.
  9. Mettez en boîtier. Faites cheminer le câble de sondes à l'écart du microcontrôleur et du quartz.
⚠️ Sécurité — les cinq règles absolues
  1. Alimentation sur piles uniquement. Jamais de secteur, jamais de bloc d'alimentation, jamais d'USB relié à un ordinateur branché pendant qu'une plante ou une personne est connectée. Si vous devez programmer la carte, débranchez d'abord les électrodes.
  2. Tension maximale 6 V. Au-delà, le courant injecté dans le végétal devient significatif et le TLC555 sort de sa plage confortable.
  3. Courant limité. Avec R2 = 10 kΩ en série et 6 V, le courant maximal en court-circuit franc est de 0,6 mA. Dans une plante de 1 MΩ, il est de 6 µA — mille fois moins que le seuil de perception humaine et sans effet physiologique connu sur un végétal.
  4. Électrodes inox 316L, argent chloruré ou or. Jamais de cuivre nu, de laiton ni de zinc au contact prolongé.
  5. Sur un être humain, appliquez en outre toutes les règles du chapitre 34 : batterie, pas de trajet thoracique chez un porteur d'implant, pas de peau lésée.

Le programme complet de l'ATmega328P

Le code reproduit ci-après est celui de MIDI_Psychogalv_328p_v021, publié par Electricity for Progress / Data Garden sur dépôt public, et explicitement désigné comme open-source firmware dans le texte du brevet US 10 909 956 lui-même. Comment lire un tableau de gamme

Chaque tableau commence par le nombre de degrés, suivi des degrés eux-mêmes exprimés en demi-tons à partir de la tonique. Ainsi scaleMajor = {7 degrés ; 1, 3, 5, 6, 8, 10, 12} correspond aux intervalles de la gamme majeure décalés d'un demi-ton par convention interne du programme.

Pour ajouter votre propre gamme, il suffit d'une ligne. Une pentatonique mineure s'écrirait int scalePenta[] = {5, 1, 4, 6, 8, 11}; et s'active par scaleSelect = scalePenta;. C'est l'une des modifications les plus gratifiantes à faire soi-même.

Remarquez que la valeur par défaut est chromatique : les auteurs du micrologiciel ont fait le choix de l'honnêteté. C'est l'application qui, plus tard, impose une gamme.

Structure de message et boucle principale
typedef struct _MIDImessage {   // un message MIDI en attente
  unsigned int type;
  int  value;        // hauteur de note, ou n° de contrôleur
  int  velocity;     // vélocité, ou valeur cible du contrôleur
  long duration;     // instant d'extinction (en millisecondes absolues)
  long period;       // cadence de rampe pour les messages de contrôle
  int  channel;
} MIDImessage;

MIDImessage noteArray[polyphony];  // les notes en cours
MIDImessage controlMessage;        // le message de contrôle en cours

void setup() {
  pinMode(knobPin, INPUT);
  randomSeed(analogRead(0));
  Serial.begin(31250);          // ← DÉBIT MIDI NORMALISÉ
  controlMessage.value = 0;
  checkBattery();               // coupe les LED si la pile est faible
  if (noteLEDs) bootLightshow();
  attachInterrupt(interruptPin, sample, RISING);  // ← démarre la mesure
}

void loop() {
  currentMillis = millis();
  checkBattery();       // surveille la pile
  checkKnob();          // relit le potentiomètre de seuil
  if (index >= samplesize) { analyzeSample(); }   // fenêtre pleine → analyse
  checkNote();          // éteint les notes arrivées à échéance
  checkControl();       // avance la rampe du message de contrôle
  checkLED();           // met à jour les fondus sans delay()
  previousMillis = currentMillis;
}
🔬 Point scientifique — une architecture non bloquante

Observez qu'il n'y a aucun delay() dans la boucle principale. Toute la temporisation repose sur la comparaison d'un horodatage absolu (currentMillis) à une échéance stockée dans chaque message.

C'est indispensable ici. La routine d'interruption se déclenche à chaque front du 555, soit environ toutes les millisecondes. Un delay(250) dans la boucle principale ferait manquer deux cent cinquante fronts, et l'analyse statistique porterait sur une fenêtre temporelle aberrante. Cette architecture — boucle rapide, échéances absolues, interruption minimale — est le modèle canonique de tout système temps réel embarqué, et c'est une bonne raison d'étudier ce code même si l'on ne construit pas l'appareil.

Le cœur : détection de changement

SampleAnalysis.ino — l'algorithme intégral
void sample()          // ROUTINE D'INTERRUPTION — front montant sur D2
{
  if (index < samplesize) {
    samples[index] = micros() - microseconds;
    microseconds   = samples[index] + microseconds;  // reconstruit micros()
                                                     // sans le rappeler
    index += 1;
  }
}

void analyzeSample()
{
  unsigned long averg = 0, maxim = 0, minim = 100000, delta = 0;
  float stdevi = 0;
  byte change = 0;

  if (index == samplesize) {                 // la fenêtre est pleine
    unsigned long sampanalysis[analysize];
    for (byte i = 0; i < analysize; i++) {
      sampanalysis[i] = samples[i+1];        // on écarte le 1er échantillon
      if (sampanalysis[i] > maxim) maxim = sampanalysis[i];
      if (sampanalysis[i] < minim) minim = sampanalysis[i];
      averg  += sampanalysis[i];
      stdevi += sampanalysis[i] * sampanalysis[i];   // somme des carrés
    }

    averg  = averg / analysize;
    stdevi = sqrt(stdevi / analysize - averg * averg);  // écart-type
    if (stdevi < 1) stdevi = 1.0;            // plancher, évite la division
    delta  = maxim - minim;

    // ═══════════ DÉTECTION DE CHANGEMENT ═══════════
    if (delta > (stdevi * threshold)) { change = 1; }
    // ═══════════════════════════════════════════════

    if (change) {
      int dur   = 150 + (map(delta % 127, 1, 127, 100, 2500));  // durée
      int ramp  = 3 + (dur % 100);                              // pente CC
      int notechannel = random(1, 5);

      int setnote = map(averg % 127, 1, 127, noteMin, noteMax); // hauteur
      setnote = scaleNote(setnote, scaleSelect, root);          // quantifie
      setNote(setnote, 100, dur, channel);

      setControl(controlNumber, controlMessage.value, delta % 127, ramp);
    }
    index = 0;    // on réarme la fenêtre
  }
}
⚠️ Trois remarques critiques sur ce code

L'écart-type est calculé de façon numériquement instable. La formule sqrt(Σx²/n − (Σx/n)²) soustrait deux grands nombres presque égaux : sur des périodes de l'ordre de 1 000 µs, les carrés atteignent 10⁶ et la perte de précision est réelle en arithmétique flottante 32 bits. Une implémentation plus robuste utiliserait l'algorithme de Welford. En pratique, cela fonctionne — mais si vous réécrivez le code, corrigez ce point.

Le % 127 est un choix arbitraire lourd de conséquences. averg % 127 replie la moyenne dans 0-126 : deux valeurs de période séparées de 127 µs donnent exactement la même note. La correspondance période → hauteur n'est donc ni monotone ni continue, mais en dents de scie. C'est musicalement intéressant — cela crée des sauts d'octave inattendus — et physiquement dénué de sens. Sachez-le quand vous interprétez une hauteur.

La vélocité est fixée à 100 et ne porte aucune information. Toutes les notes sortent avec la même force. C'est une occasion manquée : la vélocité pourrait porter delta, ce qui donnerait une dynamique réellement issue de la plante. C'est la première modification que nous suggérons à qui veut améliorer ce code.

Scale.ino — quantification sur une gamme
int scaleSearch(int note, int scale[], int scalesize) {
  for (byte i = 1; i < scalesize; i++) {
    if (note == scale[i]) return note;
    else if (note < scale[i]) return scale[i];  // 1er degré supérieur
  }
  return 6;   // valeur arbitraire plutôt qu'un échec
}

int scaleNote(int note, int scale[], int root) {
  int scaled    = note % 12;      // position dans l'octave
  int octave    = note / 12;      // numéro d'octave
  int scalesize = scale[0];
  scaled = scaleSearch(scaled, scale, scalesize);
  scaled = (scaled + (12 * octave)) + root;   // on réassemble
  return scaled;
}
MIDIserial.ino — émission de la trame
void midiSerial(int type, int channel, int data1, int data2) {
  cli();                                  // interruptions désactivées
    data1 &= 0x7F;                        // on force le bit 7 à 0
    data2 &= 0x7F;                        // (données MIDI = 7 bits)
    byte statusbyte = (type | ((channel - 1) & 0x0F));
    Serial.write(statusbyte);             // 0x9n = Note On, 0xBn = CC
    Serial.write(data1);
    Serial.write(data2);
  sei();                                  // interruptions réactivées
}
Pourquoi couper les interruptions pendant l'émission

Une trame MIDI est un triplet indissociable : octet de statut, puis deux octets de données. Si une interruption survenait entre deux Serial.write() et retardait l'émission, un synthétiseur pourrait interpréter la trame de travers.

Le commentaire du code dit « probablement inutile », et c'est exact avec le tampon série de l'Arduino — mais c'est un bon réflexe défensif qui ne coûte rien. Notez tout de même que couper les interruptions fait manquer des fronts du 555 : sur une émission de trois octets à 31 250 bauds, cela dure environ 960 µs, soit à peu près une période complète de l'oscillateur. Un échantillon perdu de temps en temps, sans conséquence sur une fenêtre de dix.

Peripherals.ino — le voltmètre secret
long readVcc() {   // mesure la tension d'alimentation SANS composant externe
  long result;
  // On mesure la référence interne de 1,1 V PAR RAPPORT à AVcc
  ADMUX = _BV(REFS0) | _BV(MUX3) | _BV(MUX2) | _BV(MUX1);
  delay(2);                          // laisse la référence s'établir
  ADCSRA |= _BV(ADSC);               // lance la conversion
  while (bit_is_set(ADCSRA, ADSC));  // attend la fin
  result  = ADCL;
  result |= ADCH << 8;
  result = 1126400L / result;        // 1,1 V × 1024 × 1000 → AVcc en mV
  return result;
}

Cette fonction est un classique de l'ATmega et mérite d'être connue : elle permet de mesurer la tension de la pile sans aucun composant, en retournant le principe du convertisseur. Au lieu de mesurer une tension inconnue par rapport à une référence connue, on mesure une référence connue (les 1,1 V internes) par rapport à l'alimentation, et l'on en déduit celle-ci. Le programme s'en sert pour éteindre les LED quand la pile descend sous 3,0 V — économisant ainsi l'essentiel de la consommation pour prolonger la mesure.

Biotron — mesure de fréquence par compteur matériel (src/raw_plant.c)
#define PLANT_PIN        13     /* broche d'entrée du signal de la plante */
#define TIMER_PLANT_MS   100    /* fenêtre de comptage, en millisecondes  */
#define TIMER_MULTIPLIER (1000 / TIMER_PLANT_MS)   /* → fronts par seconde */

void setupPwm(uint8_t freq_pin) {
    slice_num = pwm_gpio_to_slice_num(freq_pin);
    pwm_config cfg = pwm_get_default_config();
    pwm_config_set_clkdiv_mode(&cfg, PWM_DIV_B_RISING);  /* ← COMPTEUR DE
                                                              FRONTS MONTANTS */
    pwm_config_set_clkdiv(&cfg, 1);
    pwm_init(slice_num, &cfg, false);
    gpio_set_function(freq_pin, GPIO_FUNC_PWM);
    pwm_set_enabled(slice_num, true);
    /* … interruption de débordement pour étendre le compteur à 32 bits … */
}

static bool _repeating_timer_callback_t(repeating_timer_t *rt) {
    freq_ready = true;
    realFreq = _pwm_read(slice_num) * TIMER_MULTIPLIER
             + rand() % (settings.random_note * 10);   /* ← voir ci-dessous */
    return true;
}
⚠️ Une ligne qu'il faut lire attentivement

Regardez la dernière ligne du calcul de fréquence : + rand() % (settings.random_note * 10). Ce micrologiciel ajoute délibérément un nombre aléatoire à la fréquence mesurée, dans une proportion réglable par un paramètre que l'interface nomme « Ultra sensitivity ».

Ce n'est ni un bogue ni une tromperie : le paramètre est documenté publiquement, et la fonction est musicalement compréhensible — sur une plante très calme, la fréquence mesurée varie trop peu pour franchir un seuil, et le boîtier resterait muet. L'aléa relance la machine.

Mais il faut en mesurer la portée. Quand ce réglage est actif, une partie de ce que vous entendez ne vient pas de la plante : elle vient d'un générateur de nombres aléatoires. Pour toute écoute que vous présentez comme informative, mettez ce paramètre à zéro — et vérifiez que les autres appareils, qui ne publient pas leur code, n'en font pas autant sans le dire.

Voilà, incidemment, le meilleur argument en faveur du logiciel libre dans ce domaine : on ne peut vérifier que ce que l'on peut lire. Si cette ligne existe ailleurs, personne ne le saura jamais.

Le micrologiciel expose par ailleurs une trentaine de réglages, accessibles en SysEx et en Control Change, dont la nomenclature complète est publiée : tempo, taille de pas, gamme, vélocités minimale et maximale, « humanisation », répétition de note, tenue, plage du capteur de lumière, mode de pitch bend, note de référence. C'est, de loin, l'appareil le plus paramétrable du marché — et le seul dont on puisse auditer les choix.

À retenir

  • Le micrologiciel complet de l'ATmega328P est public : 426 lignes, 5 fichiers, une seule bibliothèque externe.
  • Le code de Damanhur pour le 68HC11, lui, n'est pas disponible (annexe sur microfiche).
  • Architecture non bloquante : aucun delay(), échéances absolues, interruption minimale.
  • La détection est un seuil sur delta > écart-type × seuil, avec le seuil réglé au potentiomètre.
  • Trois défauts connus : écart-type numériquement instable, correspondance en dents de scie par le % 127, vélocité constante.
  • Cinq modifications proposées, dont deux transforment l'appareil en instrument de mesure.
  • Le Biotron mesure une fréquence plutôt qu'une période — et ajoute, de façon documentée, un aléa réglable au signal.
