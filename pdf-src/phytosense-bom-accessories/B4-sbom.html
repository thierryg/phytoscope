Software bill of materials

A board has its bill of materials; the software that drives it has one too. It answers the same questions: what goes into the product, where it comes from, under which licence, and in exactly which version.

Scope and obligations

PhytoScope incorporates no third-party code: it relies on these libraries at run time. Distributed as Python sources, it satisfies in practice the substitutability obligation that Qt's LGPL licence imposes — a user can replace the library without recompiling anything.

The four native libraries in the second part of the table are reached through the Python packages. They are part of what runs on the machine, and so they belong in the inventory, even though they are not redistributed.

✦ An inventory that describes the machine, not the file

This table is not copied from a dependency file: it is established by introspecting the modules that are actually importable. It therefore describes what is installed, rather than what the project claims to require — which is precisely the point of the exercise. The command python3 tools/sbom.py regenerates it at any time; the --json option produces a CycloneDX 1.5 document, usable directly by compliance and vulnerability tooling.

Regenerating the software bill of materials
$ python3 tools/sbom.py              # human-readable
$ python3 tools/sbom.py --json       # CycloneDX 1.5
$ python3 tools/sbom.py --html       # fascicle fragment
