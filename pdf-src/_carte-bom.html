Bill of materials and accessories — PhytoSense One

This fascicle accompanies the book The PhytoSense Board. It gathers everything you have to buy: the board's components, the accessories, the tooling, and what each of those costs. It is made to be printed and ticked off.

Prices were taken in September 2026 from a European distributor, excluding tax, in single quantities. They are orders of magnitude, not commitments. Distributor part numbers are indicative: every component chosen is a catalog item, available from several suppliers.

✦ The four parts not to substitute

The ADA4530-1, the 0.1 % reference resistors, the LT3045 and LT3094 regulators, and the isolation transformer. These define what the instrument can do. Everything else accepts equivalents.

Three remarks that save time

The USB-C cable has to carry data. Many cables sold with chargers contain only the power conductors. A board that has power but is invisible to the system is almost always a cable problem.

The external battery is the best accessory of the lot. Twenty-five euros, and the last coupling path to the mains disappears. On long recordings the gain is measurable.

Isopropyl alcohol is not a finishing product. It is a manufacturing step: a flux residue between the input and the guard conducts quite enough to ruin a very high-impedance measurement.

Scope and obligations

PhytoScope incorporates no third-party code: it relies on these libraries at run time. Distributed as Python sources, it satisfies in practice the substitutability obligation that Qt's LGPL licence imposes — a user can replace the library without recompiling anything.

The four native libraries in the second part of the table are reached through the Python packages. They are part of what runs on the machine, and so they belong in the inventory, even though they are not redistributed.

✦ An inventory that describes the machine, not the file

This table is not copied from a dependency file: it is established by introspecting the modules that are actually importable. It therefore describes what is installed, rather than what the project claims to require — which is precisely the point of the exercise. The command python3 tools/sbom.py regenerates it at any time; the --json option produces a CycloneDX 1.5 document, usable directly by compliance and vulnerability tooling.

⚠️ The line item everybody forgets

It is neither a component nor a tool: it is time. Fifteen hours of assembly, three hours of acceptance testing, and an hour or so a year to redo the acceptance sheet. On top of that comes the learning, which is not wasted time but is time all the same. A commercial instrument is unboxed and works; this one is built.
