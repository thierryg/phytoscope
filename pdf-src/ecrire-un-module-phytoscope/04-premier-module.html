1. Un premier module, en dix minutes

Commençons par le faire, on expliquera ensuite. À la fin de ce chapitre, trois lignes de votre cru s'afficheront dans l'onglet Multimètre du logiciel.

Créer le squelette

Le SDK est livré avec le code source, dans le dossier sdk/. Il contient un outil qui crée un module complet :

python3 src/sdk/outils/nouveau_module.py mon-premier-module

Trois fichiers apparaissent :

FichierCe qu'il contient
module.pyle squelette, avec une capacité d'analyse qui fonctionne déjà
test_mon_premier_module.pydes essais qui passent, et qu'on étend
README.mdcomment l'installer, et ce qui reste à faire

L'intérêt de cet outil n'est pas de taper moins. C'est que le squelette produit est déjà correct : le manifeste est valide, les essais passent, et les pièges décrits plus loin sont déjà évités. On part d'un module qui marche, et l'on remplace ce qu'on veut.

L'éprouver, sans rien lancer

python3 -m pytest mon-premier-module/ -v

Cinq essais passent. Remarquez ce qu'ils n'exigent pas : ni le logiciel lancé, ni une carte branchée, ni une plante sur le bureau. Les essais fabriquent un signal plausible et un faux contexte, puis appellent votre code. C'est ce qui permet de développer un module dans le train.

Le faux contexte

Il est fourni avec les essais, et vous le recopierez. Il implémente ce dont votre module se sert, et rien d'autre. Si un essai échoue parce qu'une méthode y manque, c'est le signe que vous employez une partie de l'interface qu'il faudra aussi éprouver — ce qui est une bonne nouvelle, pas un ennui.

L'installer

# Linux
cp -r mon-premier-module ~/.config/phytoscope/modules/

# macOS
cp -r mon-premier-module ~/Library/Application\ Support/PhytoScope/modules/

# Windows
xcopy /E mon-premier-module %APPDATA%\PhytoScope\modules\mon-premier-module\

Relancez PhytoScope. Votre module apparaît à deux endroits : dans l'onglet Multimètre → Grandeurs scientifiques, où ses valeurs s'affichent parmi celles des modules livrés ; et dans l'onglet Diagnostic → Modules, qui liste ce qui est chargé.

Si rien n'apparaît

Allez au Diagnostic. La page Modules dit en une phrase ce qui s'est passé. C'est la page qu'on regarde en premier, avant de douter de soi :

Ce qui s'afficheCe que cela signifie
incompatible — vise l'API 2.0 votre manifeste annonce une version d'interface que ce logiciel ne connaît pas. Corrigez api=.
incompatible — bibliothèque absente vous avez déclaré exige=("scipy",) et scipy n'est pas installé. La commande à taper est donnée.
en_faute — TypeError au chargement votre code a levé. La trace complète est dans le journal (Ctrl+L).
desactive l'utilisateur l'a désactivé dans les réglages.
absent de la liste le dossier n'est pas au bon endroit, ou il ne contient pas de fichier module.py.
